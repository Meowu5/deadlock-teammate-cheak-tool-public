# 数据获取、原因与注意事项

## 本地采集为什么需要桥接记录

本工具的主采集路径读取本机已有游戏日志。普通日志并不保证包含可用于识别完整本局名单的稳定账号字段；QoL 桥接记录用于提供可验证的身份和采集帧线索。只出现昵称、英雄、连接提示或桥接加载提示，均不足以证明已获得完整名单。

正式支持的精确适配目标是 **QoL Lock 4.0.5 hotfix**：

- [QoL Lock 模组页面](https://gamebanana.com/mods/650634)
- [对应更新 461898](https://gamebanana.com/updates/461898)
- 上游包名：`qollock_405_6octoberhotfix.zip`

这里的支持范围是精确版本兼容适配，不代表每个标为 4.0.5 的包都一致，也不是对当前电脑实际加载模组或每场对局的证明。游戏、模组或日志格式变化后，来源可能转为未知或不兼容。设置页只做检测；安装、修复、卸载、回退入口在本版本中不可用。

## 来源状态应如何理解

| 状态或来源 | 能说明什么 | 不能据此认定什么 |
| --- | --- | --- |
| 桥接兼容／脚本已加载 | 检测或日志握手满足相应条件 | 已有完整、实时的本局名单 |
| 等待采集帧／没有名单 | 目前没有可用名单证据 | 本局没有其他玩家 |
| 数据不完整／身份未知 | 仅保存已有证据，仍有缺项 | 缺项为零，或已补齐全部玩家 |
| Steam 候选 | 实验备用路径返回待确认的候选 | 候选必然参与当前对局，或其阵营已确定 |
| 人工确认／人工备注 | 使用者明确添加或确认的信息 | 游戏原生证明、官方评价或自动验证 |
| 历史补充完成 | 本次确认范围内的一次补充操作已完成 | 所有游戏历史均已被外部服务收录 |

遇到不完整数据，优先查看来源和时间范围。昵称或英雄相同不足以合并玩家；未知字段保持未知，不用猜测值填满列表。

## 历史补充与外部网页

历史补充按界面要求选择本人账号、游戏模式和查询范围，经确认后访问注明的数据来源。查询会向相应服务发送取得该范围数据所需的账号或比赛标识，并产生普通网络元数据。未收录、限流、网络失败和缺失字段会限制可获得的内容；请根据返回状态决定重试或人工补充。

现有 Deadlock API 历史补充入口与 Statlocker 自动补抓是不同能力。**v0.1.3 暂不接入 Statlocker 自动补抓，现有数据获取方式保持不变。** 相关任务显示“等待接口接入”时，到期也不会因此自动发起补抓请求，更不会标成成功。仍可按现有比赛修正等入口人工补充。点击 Statlocker 网页链接会由浏览器打开相应账号或比赛页面；网页跳转不等于 API 接入或导入成功。

## Steam 备用为何默认关闭

Steam 备用属于实验功能。真实 Steam 客户端／DLL 版本组合、初始化与实战名单尚未完成验收；缺少必要连接证据、接口不兼容或数据过期时应停止候选流程。保持默认关闭不影响已具备有效 QoL 桥接日志的主路径或本地查询、备注。

即使候选能够读取，Steam 在线、同一服务器或相关成员信息也不自动证明某人参加当前 Deadlock 对局。需要你按界面确认参与者；未知阵营、身份或缺项仍保留，不宣称备用路径完整自动采集。

## 本地资料与对外请求

玩家记录、备注、头像和配置保存在所选本地资料目录。主日志采集本身不上传原始日志；历史查询、外部网页跳转和软件更新检查各有独立用途，不能据此宣称应用完全离线。

软件更新检查访问本公开下载仓库的 GitHub Release 元数据；它不需要玩家日志、数据库、备注或账号 ID。诊断或反馈材料应先核对并脱敏，再由你选择是否提交。不要在公开 Issue 中附上真实数据库、原始日志、访问密钥或个人目录信息。

本工具和所用模组不构成 Valve 或反作弊系统的批准；不能承诺零封禁风险。使用前请自行查看适用的游戏、平台和模组说明。
